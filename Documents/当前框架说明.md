# 当前代码框架说明

本文按当前仓库实现描述系统结构，用于接手开发、答辩讲解和文档对齐。

## 一、整体结构

项目是一个 Kotlin Android 应用，主模块为 `app`。当前实现以单 Activity 承载大厅、房间和牌桌界面，核心游戏逻辑独立放在 `model`、`rule`、`controller`、`ai`、`network` 等包中。

```text
app/src/main/java/com/scut/chudadi/
├── MainActivity.kt          # Android 入口、界面渲染、本地/蓝牙流程编排
├── model/                   # 牌、玩家、局面、牌型等数据结构
├── rule/                    # 南方/北方规则、牌型识别、出牌比较
├── controller/              # 发牌、出牌、过牌、轮转、结算
├── ai/                      # AI 出牌候选和策略
├── network/                 # 蓝牙协议、编解码、RFCOMM 连接管理
└── ui/                      # 轻量 ViewModel 适配层
```

资源目录位于 `app/src/main/res`，包含大厅和牌桌布局、按钮背景、牌面样式、头像、牌背、牌桌背景和音效。

## 二、核心模块职责

| 模块 | 主要文件 | 当前职责 |
| --- | --- | --- |
| `model` | `Card.kt`、`GameState.kt`、`HandType.kt` | 定义花色、点数、牌、玩家、配置、局面状态和出牌结果。 |
| `rule` | `RuleProfile.kt`、`HandEvaluator.kt`、`RuleEngine.kt` | 定义南方/北方规则口径，识别牌型，判断能否出牌/过牌，比较当前牌与上一手。 |
| `controller` | `GameController.kt` | 生成牌堆并按 seed 发牌，维护当前玩家、上一手、过牌数、完成顺序和结算结果。 |
| `ai` | `PlayCandidateFinder.kt`、`GreedyStrategy.kt`、`ConservativeStrategy.kt` | 枚举合法候选牌，贪心策略选择最小合法牌，保守策略选择排序后较大的合法牌。 |
| `network` | `BluetoothProtocol.kt`、`BluetoothMessageCodec.kt`、`BluetoothGameSyncManager.kt` | 定义房间/准备/开局/出牌/过牌/快照/私人手牌/心跳/重连消息，并通过经典蓝牙 RFCOMM 收发。 |
| `ui` | `GameViewModel.kt` | 对 `GameController` 做轻量封装；当前主要流程仍由 `MainActivity` 直接调度。 |

## 三、一局游戏的数据流

1. `MainActivity` 根据大厅选择创建本地 AI 房间或蓝牙房间。
2. `startNewGame(seed)` 根据大厅规则选择创建 `GameConfig` 和 4 个 `PlayerState`。
3. `GameController.startGame(seed)` 洗牌、发牌，并通过当前 `RuleProfile.selectFirstPlayer` 决定先手。
4. 玩家或 AI 选择牌后，`RuleEngine.canPlay` 按当前规则校验手牌归属、牌型、首轮限制和压制关系。
5. `GameController.playCards` 移除手牌、记录上一手、清空过牌数，并在有人出完时更新 `finishOrder`。
6. `GameController.pass` 在桌面存在上一手时增加过牌数；所有需要响应的玩家都过牌后清空桌面。
7. `MainActivity` 为当前玩家维护 20 秒回合倒计时；超时后可过牌时自动过牌，不可过牌时自动选择一手合法牌。
8. 任意玩家手牌出完后，控制器立即判定本局结束，不再继续轮转。
9. `finishRound` 调用 `settleRound`：赢家记第 1 名，未出完玩家按剩余手牌数从少到多补齐名次，并按 `+3 / +1 / -1 / -3` 累计比分。

## 四、本地与 AI 对局

本地模式固定使用 `p1` 作为真人玩家，`p2`、`p3`、`p4` 为 AI。玩家点击提示时，`PlayCandidateFinder` 会枚举当前合法出牌并选择最靠前候选；AI 轮次由 `runAiTurns` 延迟执行，避免界面瞬间连续跳过。

当前两种策略：

- `GreedyStrategy`：选择排序后的第一个合法候选，倾向尽快用小牌跟牌。
- `ConservativeStrategy`：选择排序后的最后一个合法候选，表现为更激进地压牌。

## 五、蓝牙联机框架

蓝牙模式下，房主本地座位固定为 `p1`。房主可将 `p2`、`p3`、`p4` 设置为蓝牙真人或 AI 托管。客户端加入后由房主分配座位，客户端收到 `SeatAssigned` 后自动发送 `Ready`。

主要同步策略：

1. 房主生成开局 seed，并把 seed 与规则类型广播到 `StartGame`、`RoomState` 和 `GameStateSnapshot`。
2. 房主维护权威 `GameController` 状态。
3. 客户端出牌/过牌只发送 `PlayCards` / `Pass` 请求，不直接推进本地权威状态。
4. 房主校验远端请求，合法后广播动作和 `GameStateSnapshot`。
5. 公共快照只广播当前玩家、上一手、手牌数、比分、完成顺序等公开信息。
6. 客户端自己的手牌通过 `PrivateHand` 单独发送，避免把所有玩家手牌放进公共快照。
7. `Heartbeat` 携带玩家座位号；房主检测超时后可标记座位离线，并由 AI 暂时代管。
8. 客户端收到开局或快照后会进入实时牌桌并切到房主规则；手动重连后发送 `Reconnect`，房主重新广播房间状态、开局 seed、公共快照和私人手牌。
9. 回合倒计时在房主端作为权威推进；客户端只会在轮到自己且超时时发送出牌或过牌请求，随后等待房主快照确认。

## 六、测试覆盖

当前单元测试位于 `app/src/test/java/com/scut/chudadi`：

- `HandEvaluatorTest`：覆盖南方 `A2345` 顺子、北方拒绝 `A2345` 和同花顺识别。
- `RuleEngineTest`：覆盖南方首轮方块 3、北方首轮放宽和同点数花色比较差异。
- `GameControllerTest`：覆盖南方/北方先手选择、发牌 seed 稳定性、首个玩家出完即结束、结束后禁止继续行动和结算顺序。
- `BluetoothMessageCodecTest`：覆盖加入房间、座位分配、房间状态、规则同步、心跳、快照、私人手牌等消息往返。
- `CardWireCodecTest`：覆盖单张牌传输编码和非法值处理。

## 七、当前边界与后续整理方向

1. `MainActivity` 承担了界面渲染、房间状态和蓝牙编排，后续若继续扩展，可拆出房间协调器和桌面渲染组件。
2. 附近设备扫描尚未实现，当前通过系统已配对设备或手动输入主机 MAC 地址/设备名加入；客户端不要填写房主随机房间号。
3. 报单提醒已在 UI 层根据手牌数量显示；`顶大` 强制出牌规则尚未进入当前控制器。
4. 蓝牙重连是手动入口，后台自动重连和长时间稳定性仍需真机测试补证据。
