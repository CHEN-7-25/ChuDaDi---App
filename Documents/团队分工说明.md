# 锄大地安卓项目团队分工说明（4人）

本文按当前仓库框架重新整理分工，重点从“从零开发计划”调整为“现有代码维护、完善和答辩交付”。

## 一、当前交付目标

项目当前已经具备：

- Android 工程骨架和单 Activity 对局界面。
- 本地 1 人 + 3 AI 对局。
- 南方规则实现。
- 牌型识别、出牌校验、过牌、轮转、排名结算。
- 贪心/保守两种 AI 策略。
- 经典蓝牙主机/客户端连接、座位分配、准备、开局 seed、公共快照、私人手牌、心跳和手动重连。
- 规则、控制器和网络编解码单元测试。

后续团队工作的重点是：稳定性验证、文档对齐、答辩材料和少量规则/体验补强。

## 二、成员分工

### 成员 A（组长 / 集成 / 文档）

负责内容：需求口径、文档一致性、版本集成、答辩材料。

主要任务：

1. 维护 `README.md`、`Documents/*` 和最终汇报材料。
2. 统一规则口径，确保代码、测试和文档描述一致。
3. 组织每次合并前的构建、测试和真机演示验收。
4. 记录风险清单、缺陷列表和版本说明。

交付物：

1. 项目总览与当前框架说明。
2. 答辩演示流程和讲解提纲。
3. 最终测试结论与问题记录。

### 成员 B（核心逻辑 / 规则 / 测试）

负责内容：`model`、`rule`、`controller` 和核心单元测试。

主要任务：

1. 维护 `Card`、`PlayerState`、`GameState`、`HandType` 等数据结构。
2. 维护 `SouthRuleProfile`、`HandEvaluator` 和 `RuleEngine`。
3. 补充五张牌边界测试、南方规则测试和结算测试。
4. 如需新增“顶大”/报单等规则，先写测试再改控制器。

交付物：

1. 核心规则代码和测试用例。
2. 南方规则说明。
3. 缺陷修复记录。

### 成员 C（Android UI / 交互体验）

负责内容：`MainActivity`、`res/layout`、`res/drawable`、`res/values` 和界面资源接入。

主要任务：

1. 维护大厅、房间、牌桌和结算状态在单 Activity 中的展示。
2. 保证选牌、出牌、过牌、提示、下一局、返回房间等操作清晰可用。
3. 适配常见手机屏幕，检查文字、按钮和手牌区域是否重叠。
4. 配合成员 D 展示蓝牙房间状态、准备状态、离线状态和重连入口。

交付物：

1. UI 关键流程截图。
2. 交互问题清单和修复记录。
3. 真机演示前的界面验收结果。

### 成员 D（蓝牙联机 / AI）

负责内容：`network`、`ai` 和联机流程验证。

主要任务：

1. 维护 `BluetoothMessage`、`BluetoothMessageCodec`、`BluetoothGameSyncManager` 和 `CardWireCodec`。
2. 验证主机/客户端连接、座位分配、准备、开局、快照、私人手牌、心跳和重连。
3. 维护 `PlayCandidateFinder`、`GreedyStrategy`、`ConservativeStrategy`。
4. 记录蓝牙真机测试结果，定位连接失败、消息丢失或状态不同步问题。

交付物：

1. 蓝牙联机测试记录。
2. 网络协议说明和编解码测试。
3. AI 策略说明和演示样例。

## 四、协作流程

1. 每个功能或修复从 `feature/*` 分支开始，完成后合并到集成分支。
2. 涉及规则变化时，必须同步修改规则文档和单元测试。
3. 涉及蓝牙协议变化时，必须同步修改 `BluetoothMessageCodecTest` 和蓝牙测试记录。
4. 涉及资源变化时，必须补充 `资源授权说明.md`。
5. 答辩前至少完成一次本地对局演示和一次蓝牙双机演示。

## 五、剩余工作节奏

1. 第 1 阶段：跑通本地对局和单元测试，确认规则口径。
2. 第 2 阶段：完成蓝牙双机联调，记录设备和问题。
3. 第 3 阶段：修复 UI 展示、异常提示和联机状态同步问题。
4. 第 4 阶段：整理 UML、截图、测试结论和答辩讲解材料。
