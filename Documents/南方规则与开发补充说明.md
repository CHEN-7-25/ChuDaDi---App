# 南方规则与开发补充说明

## 一、说明目的

本文记录当前代码中“南方规则”的可执行定义。当前 App 已恢复南方/北方规则选择；本文专门说明南方规则，北方差异见《锄大地游戏规则设计》。它不是泛泛的地方规则百科，而是和 `SouthRuleProfile`、`HandEvaluator`、`RuleEngine`、`GameController` 保持一致的工程说明。

## 二、当前规则口径

| 规则点 | 当前实现 |
| --- | --- |
| 首轮限制 | 首手必须包含方块 3。 |
| 首轮先手 | 方块 3 持有者先出。 |
| 同点数比较 | 点数相同时继续比较花色。 |
| `A2345` 顺子 | 允许，最大点数按 5 处理。 |

花色顺序由 `Suit.order` 定义：方块 < 梅花 < 红桃 < 黑桃。点数顺序由 `Rank.order` 定义：3 < 4 < ... < K < A < 2。

## 三、牌型与比较

当前支持的牌型来自 `HandType`：

1. 单张 `SINGLE`
2. 对子 `PAIR`
3. 三条 `TRIPLE`
4. 四炸 `BOMB4`
5. 顺子 `STRAIGHT`
6. 同花五 `FLUSH5`
7. 葫芦 `FULL_HOUSE`
8. 铁支 `FOUR_PLUS_ONE`
9. 同花顺 `STRAIGHT_FLUSH`

五张牌型等级为：同花顺 > 铁支 > 葫芦 > 同花五 > 顺子。非五张牌只能和相同张数、相同基础牌型比较；当前比较逻辑以主要点数为主，主要点数相同时继续比较主要花色。

## 四、关键实现文件

- `app/src/main/java/com/scut/chudadi/rule/RuleProfile.kt`：定义南方/北方规则名称、先手选择和规则差异开关。
- `app/src/main/java/com/scut/chudadi/rule/HandEvaluator.kt`：识别牌型，处理 `A2345` 特例。
- `app/src/main/java/com/scut/chudadi/rule/RuleEngine.kt`：判断出牌合法性、压制关系和是否可过牌。
- `app/src/main/java/com/scut/chudadi/controller/GameController.kt`：调用规则层推进发牌、出牌、过牌、轮转和结算。

## 五、测试覆盖点

当前已有测试覆盖：

1. `A2345` 顺子识别。
2. 首轮必须带方块 3。
3. 同点数时可用花色继续比较。
4. 首轮由方块 3 持有者先手。
5. 固定 seed 发牌可复现，适合蓝牙联机同步。
6. 首个玩家出完即结束、过牌清桌和按剩余手牌数补齐名次的积分结算。

## 六、当前未实现或需明确的规则

1. “顶大”/报单提醒尚未进入控制器，目前只在规则设计文档中保留为扩展项。
2. 当前默认计分模式为赢家记第 1 名，其余玩家按剩余手牌数补齐名次并累计 `+3 / +1 / -1 / -3`；`WIN_COUNT` 模式只记录赢家胜场。
3. 若答辩规则口径变化，应先补单元测试，再改 `SouthRuleProfile`、`NorthRuleProfile`、`HandEvaluator` 或 `RuleEngine`。
